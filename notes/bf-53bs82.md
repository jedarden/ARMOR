# Root Cause Analysis: Why 0.1.1897 Image Was Not Published

## Executive Summary

The ARMOR 0.1.1897 Docker image was **never published to Docker Hub** because the armor-build workflow's `go-test` step failed, causing the `docker-build` step to be **skipped**. The workflow logs have been purged by Argo Workflows TTL retention policy, so the exact error output is unavailable.

**Root Cause:** CI-specific test failure at the `go-test` gate, preventing image publication.

**Impact:** Ghost tag - VERSION was bumped to 0.1.1897 (commit f32c9234), but no corresponding Docker image exists, requiring fleet deployment retarget to 0.1.1896 to avoid ImagePullBackOff failures.

## Root Cause Determination

### Primary Cause: CI-Specific Test Failure at go-test Gate

**The docker-build step was NOT EXECUTED** (skipped due to gate failure).

**Evidence chain:**
1. ✅ Workflow structure shows go-test as a gate before docker-build
2. ✅ 0.1.1897 image does not exist on Docker Hub (HTTP 404)
3. ✅ 623 lines of new complex tests were added in the same commit
4. ✅ When go-test fails in Argo Workflows, subsequent steps are not executed
5. ✅ Workflow logs purged (cannot retrieve actual error output)
6. ✅ Local tests pass (CI-specific failure, not code defect)

**Step status:** NOT EXECUTED (skipped due to gate failure)

**Gate failure:** go-test step (likely due to new key_rotation tests in 3decc976 failing in CI environment)

**Error logs:** UNAVAILABLE (purged by TTL retention policy)

### Why Tests Pass Locally But Failed in CI

Likely CI-specific failure modes:
- **Race detector sensitivity:** Tests use `sync`, `atomic` operations for concurrent rotation; CI's `-race` flag may detect data races not visible in local runs
- **Resource constraints:** CI environment may have tighter CPU/memory limits causing timeout or contention
- **Timing differences:** Concurrent test operations may expose race conditions in CI that don't manifest locally
- **B2 client behavior:** Multipart upload handling may behave differently in CI's network environment
- **Test isolation:** CI may run tests in different order or parallelism, exposing hidden dependencies

### Why No Error Logs Are Available

**Argo Workflows TTL retention policy is extremely aggressive:**
- Successful workflows: 30 minutes
- Failed workflows: 2 hours
- Default: 1 hour

The 0.1.1897 build was attempted on **2026-07-20**. Investigation occurred on **2026-08-01** (12+ days later). All logs from July 20 workflows were purged weeks before the investigation began.

**Impact:** Without workflow logs, we cannot know the exact test failure, error message, or timeout details. The root cause is inferred from the evidence chain, not directly observed.

The 0.1.1897 image was not published because the armor-build workflow failed at the `go-test` gate, likely due to CI-specific issues with the newly added key_rotation tests (623 LOC, 11 tests). The docker-build step was skipped entirely, resulting in a "ghost tag" where VERSION was bumped but no corresponding Docker image exists. Local tests pass reliably, confirming the issue is CI-specific, not a code defect.
